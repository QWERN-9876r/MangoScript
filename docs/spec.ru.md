# MangoScript — черновик спецификации v0

[English](spec.md) · **Русский**

> Статус: черновик, всё можно менять. Нерешённые вопросы собраны в разделе «Открытые вопросы».

MangoScript — язык с семантикой JavaScript, синтаксисом в духе Go и статической типизацией.
Компилируется в читаемый JavaScript (ES-модули), типы при компиляции стираются.

## Принципы

1. **Семантика JS.** Те же значения, объекты, классы, замыкания, модули и стандартная библиотека
   (`console`, `Math`, `JSON`, методы массивов и строк).
2. **Синтаксис Go там, где он удобнее:** `func`, тип после имени, множественный возврат, `defer`,
   нулевые значения, условия без скобок, единственный цикл `for`, `switch` без `break`, без точек
   с запятой.
3. **Статическая типизация с null-safety.** Ошибки типов находит компилятор; `null` можно
   присвоить только типу, который это явно разрешает. В JS-коде типов нет.
4. **Совместимость с JS.** Из MangoScript можно импортировать любой JS-модуль, а скомпилированный
   модуль можно использовать из JS.

## 1. Лексика

### Комментарии

`// до конца строки` и `/* блок */`.

### Точки с запятой

Их пишут только чтобы разделить несколько операторов в одной строке. В остальных случаях лексер
ставит их сам по правилу Go: в конце строки, если последний токен —

- идентификатор или литерал (число, строка, `true`, `false`, `null`);
- `this`, `return`, `break` или `continue`;
- `++`, `--`, `)`, `]`, `}`.

Отсюда, как и в Go:

- открывающая `{` стоит на той же строке, что `if`, `for`, `func`, `class`;
- при переносе длинного выражения бинарный оператор оставляют в конце строки;
- перед `}` точка с запятой не нужна: `if ok { return x }`.

**Отличия от Go:** точка с запятой не ставится, если следующая строка начинается

- с `.` или `?.` — поэтому работают привычные цепочки вызовов;
- с закрывающей скобки `)`, `]` или `}` — поэтому запятая после последнего элемента
  многострочного списка не обязательна.

```go
const names = users
    .filter(u => u.active)
    .map(u => u.name)

const point = {
    x: 1,
    y: 2
}
```

### Литералы

- Числа как в JS: `42`, `3.14`, `1e3`, `0xff`, `1_000_000`.
- Строки: `"..."`, `'...'` и шаблонные `` `Hello, ${name}` ``.
- `true`, `false`, `null`.
- Массивы `[1, 2, ...rest]` и объекты `{ name: "Ann", age, "content-type": t, ...defaults }`
  (сокращённая запись `age` и spread — как в JS).

### Ключевые слова

```
func  comp  return  let  const  type  interface  class  extends  new  this  super
if  else  for  in  break  continue  switch  case  default  defer
try  catch  finally  throw  import  export  async  await  go
null  true  false  typeof  instanceof
```

Внутри объявления класса ключевыми словами считаются ещё `static`, `private`, `protected`,
`public` и `implements`, в `import` и `export` — `from`, в начале оператора в теле компонента —
`state`, `derived`, `ref`, `style`, `mount` и `effect`, в начале объявления на верхнем уровне — `dec`, после его
параметров — `needs`, а в теле декоратора — `public`. В остальных местах это обычные имена; `get`
особый только в `get(@имя.член)`. Зарезервировано на
будущее: `map`. Декораторы пишутся перед `comp`: `@html-tag` (см.
«Веб-компоненты») и объявленные через `dec` (см. «Декораторы»).

После `.` и в ключах объектов ключевые слова можно использовать как обычные имена:
`xs.map(f)`, `event.type`, `{ default: 1 }`.

Предопределённые идентификаторы (не ключевые слова, их можно перекрыть): типы `number`, `string`,
`bool`, `any`, `error` и функция `error()`.

Имена, которые начинаются с `$$`, зарезервированы за сгенерированным кодом (`$$defer`, `$$0`).
Имена, допустимые в MangoScript, но запрещённые в JS (`delete`, `static`, `function`…), в
выходном коде получают суффикс `$`: `delete` → `delete$`.

## 2. Переменные

```go
let count = 0              // тип выводится: number
let name string = "Ann"
let total number           // нулевое значение: 0
const PI = 3.14
let a, b = 1, 2
```

```js
let count = 0;
let name = "Ann";
let total = 0;
const PI = 3.14;
let a = 1, b = 2;
```

`const` переприсвоить нельзя, это проверяет компилятор.

Множественное присваивание, как в Go:

```go
a, b = b, a                // → [a, b] = [b, a];
```

### Нулевые значения

Переменная или поле класса без начального значения получает нулевое значение своего типа,
как в Go:

| Тип                        | Нулевое значение                  |
| -------------------------- | --------------------------------- |
| `number`                   | `0`                               |
| `string`                   | `""`                              |
| `bool`                     | `false`                           |
| `[]T`                      | `[]` (каждый раз новый массив)    |
| `?T`, `error`, `any`       | `null`                            |
| классы, интерфейсы, `func` | нет — значение нужно указать явно |

```go
let u User                 // ошибка: у User нет нулевого значения
let u ?User                // можно: u == null
```

### Переменная в собственном инициализаторе

Переменная существует с начала своего объявления, как в JS. Функция в её инициализаторе
выполняется позже самого инициализатора, поэтому может использовать переменную:

```go
const timer = setInterval(() => {
    if done() {
        clearInterval(timer)
    }
}, 1000)

const fact = func(n number) number {
    return n <= 1 ? 1 : n * fact(n - 1)
}
```

То же верно для обработчиков событий в разметке: `const close = <button onClick={close.remove()}>`.

Тело такой функции проверяется, когда у переменной уже есть тип. Это работает, если тип функции
известен без её тела: `func`-литерал, обработчик события или колбэк, типы параметров и результат
которого задаёт вызов. Иначе тип переменной пишется явно:

```go
const fib = (n number) => fib(n - 1)            // ошибка: у fib нужно написать тип
const fib func(number) number = n => n < 2 ? n : fib(n - 1) + fib(n - 2)
```

Использование вне функций читает переменную раньше, чем у неё появится значение: в JS это
`ReferenceError`, здесь — ошибка компиляции. В Go `x := x + 1` во вложенной области видимости
берёт внешний `x`; в MangoScript, как в JS, это новая переменная, поэтому компилятор просит другое
имя:

```go
const x = 1
func f() {
    const x = x + 1    // ошибка: здесь x — новая переменная, у неё ещё нет значения
}
```

Правило взято из JS, потому что объявление компилируется в такое же объявление JS; компилятор лишь
сообщает при компиляции то, что упало бы при выполнении.

## 3. Типы

| MangoScript       | Значения                                   | В JS                |
| ----------------- | ------------------------------------------ | ------------------- |
| `number`          | числа                                      | `number`            |
| `string`          | строки                                     | `string`            |
| `bool`            | `true`, `false`                            | `boolean`           |
| `any`             | что угодно, проверки отключены             | —                   |
| `error`           | ошибка или `null`                          | `Error` или `null`  |
| `[]T`             | массив                                     | `Array`             |
| `?T`              | значение типа `T` или `null`               | значение или `null` |
| `func(A, B) R`    | функция                                    | функция             |
| `(a A) => R`      | тот же тип функции, записанный стрелкой    | функция             |
| `comp(a A)`       | компонент, который тег берёт из значения   | функция             |
| `A \| B`          | значение типа `A` или типа `B`             | значение            |
| `"all"`, `42`     | ровно это значение                         | значение            |
| `{ x number }`    | объект с такими полями                     | объект              |
| `{ [string]: T }` | объект-словарь: любые ключи, значения `T`  | объект              |
| имя класса        | экземпляр класса                           | экземпляр класса    |
| имя интерфейса    | любое значение с нужными полями и методами | —                   |

Тип пишется после имени без двоеточия: `x number`, `xs []string`, `cb func(number) bool`,
`user ?User`.

Типизация **структурная**, как в TypeScript: значение подходит под тип, если у него есть все нужные
поля и методы нужных типов.

- **Тип функции стрелкой,** `(paths []string) => Shape`, — то же, что `func([]string) Shape`;
  имена параметров только поясняют их, а `=> void` значит «без результата». Скобки с одним типом
  без стрелки по-прежнему группируют: `[](string | number)`.
- **Объект-словарь,** `{ [string]: number }`, имеет любые ключи со значениями этого типа; ключ —
  `string` или `number`. Литерал объекта или другой объект подходит, если подходят все его поля.
  `scores["ann"]` и `scores[name]` — это `number`, а `delete scores[name]` удаляет ключ.

### Объявление типов

```go
type ID string
type Handler func(string) bool
type Pair { first, second number }
```

`type` даёт типу другое имя: `ID` и `string` взаимозаменяемы (в Go это были бы разные типы).
Для формы объектов обычно используют интерфейсы (раздел 8).

### Union и литеральные типы

```go
type Filter "all" | "active" | "done"

func show(value string | number) string {
    if typeof value == "string" {
        return value.toUpperCase()
    }
    return value.toFixed(2)         // здесь value уже number
}
```

- **`A | B`** — значение одного из типов. Скобки группируют: `[](string | number)`,
  `?(A | B)`. `?` относится к ближайшему типу, а `func() A | B` — функция, которая возвращает
  union.
- **Литеральный тип** `"all"`, `42` или `true` допускает только это значение. Union литералов ловит
  опечатки: `filter = "activ"` и `filter == "activ"` — ошибки.
- **Член union** можно использовать, если он есть у всех типов: у `string | number` есть
  `toString()`, но нет `length`. Чтобы добраться до остального, тип сужают (раздел 11).
- Литерал в коде получает литеральный тип только там, где его ожидают: `let f = "all"` — это
  `string`, а `let f Filter = "all"` — `"all"`.
- Ветки `?:`, элементы массива и разные `return` функции без объявленного результата разных типов
  дают union: `[1, "a"]` — это `[](number | string)`.
- У union и литеральных типов нет нулевого значения: `let f Filter` нужно инициализировать.
- **Поле по ключу с известным значением:** `point["x"]` или `point[axis]` при `axis "x" | "y"` —
  поле объекта (или union его полей). Ключ, которого нет среди полей, — ошибка.

### Дженерики

Параметры типа пишутся в квадратных скобках после имени, как в Go:

```go
func first[T any](xs []T) ?T {
    return xs.length > 0 ? xs[0] : null
}

interface Box[T] {
    value T
}

type Pair[A, B any] { first A; second B }

class Stack[T] {
    private items []T
    push(item T) { this.items.push(item) }
    pop() ?T { return this.items.pop() ?? null }
}

const n = first([1, 2, 3])              // ?number
let b Box[string] = { value: "a" }
let s Stack[number] = new Stack()
```

- **Ограничение** пишется после имени: `[T Named]` — `T` должен подходить под `Named`, и у
  значений типа `T` есть члены `Named`. `any` — без ограничения, тогда членов у `T` нет.
  Несколько имён подряд делят одно ограничение: `[K, V any]`. Для интерфейсов, классов и `type`
  ограничение можно не писать: `interface Box[T]`.
- **Аргументы типа** пишутся только в типах: `Box[number]`, `Pair[string, ?number]`. При вызове
  функции и в `new` они выводятся из аргументов, а если не получилось — из ожидаемого типа:
  `let xs []number = empty()`. Явного `first[number](xs)` нет: в выражении это неотличимо от
  индекса. Если вывести тип не из чего, это ошибка: `let s = new Stack()`.
- Внутри функции `T` — отдельный тип: `return 1` в функции с результатом `T` — ошибка. Нулевого
  значения у `T` нет.
- Тип может ссылаться на себя: `interface Tree[T] { value T; children []Tree[T] }`.
- `Box[number]` и `Box[string]` — разные типы, `Stack[number]` и `Stack[string]` — тоже.
- Наследоваться от обобщённого класса пока нельзя: `extends Stack[number]` в JS было бы
  индексом. Методы со своими параметрами типа (`map[U any](...)`) тоже пока не поддерживаются.
- В JS дженерики стираются, как в TypeScript.

### null и null-safety

«Пустое» значение в языке одно — `null`; `undefined` в MangoScript нет. Обычное `==`
компилируется в `===`, но сравнение с `null` остаётся нестрогим: `x == null` → `x == null`.
Поэтому оно ловит и `null`, и `undefined`, пришедший из JS-кода.

`null` можно присвоить только типам `?T`, `error` и `any`. Чтобы обратиться к полю или методу
значения типа `?T`, тип нужно сначала сузить:

```go
func findUser(id number) ?User { ... }

const u = findUser(1)
console.log(u.name)                  // ошибка: u может быть null
console.log(u?.name)                 // можно: тип ?string
console.log(u?.name ?? "anonymous")  // можно: тип string

if u != null {
    console.log(u.name)              // здесь у u тип User
}

if u == null {
    return
}
console.log(u.name)                  // и здесь: при null функция уже вышла
```

- Сужение работает для локальных переменных и параметров. Значение поля (`this.user`) сначала
  кладут в `const`.
- `error` всегда допускает `null`, писать `?error` не нужно.
- `xs[i]` имеет тип `T`, а не `?T`: выход за границы массива компилятор не ловит (так же по
  умолчанию в TypeScript).
- Значения типа `any`, в том числе всё, что импортировано из JS-модулей без типов, не
  проверяются.

## 4. Функции

```go
func add(a, b number) number {
    return a + b
}

func greet(name string) {          // без типа результата — ничего не возвращает
    console.log(`Hello, ${name}`)
}
```

```js
function add(a, b) {
  return a + b;
}

function greet(name) {
  console.log(`Hello, ${name}`);
}
```

Соседние параметры одного типа можно сгруппировать: `a, b number` — то же, что
`a number, b number`.

Объектный тип результата берётся в скобки, иначе его `{` не отличить от тела функции:
`func origin() ({ x, y number }) { ... }`.

### Множественный возврат

```go
func divmod(a, b number) (number, number) {
    return Math.floor(a / b), a % b
}

const q, r = divmod(17, 5)
const _, rest = divmod(17, 5)      // _ пропускает значение
```

```js
function divmod(a, b) {
  return [Math.floor(a / b), a % b];
}

const [q, r] = divmod(17, 5);
const [, rest] = divmod(17, 5);
```

Правила, как в Go:

- несколько значений можно только вернуть через `return` и сразу разложить по переменным
  в `let`/`const` или в присваивании;
- число переменных должно совпадать с числом значений;
- `divmod(17, 5) + 1` — ошибка компиляции.

### Анонимные функции

```go
const square = func(x number) number { return x * x }
const sum = (a, b number) => a + b
const doubled = nums.map(x => x * 2)      // тип x берётся из контекста
```

Стрелочные функции — как в JS, только с типами в стиле Go. Если тип параметра нельзя вывести из
контекста, его нужно указать.

`func`-литерал тоже компилируется в стрелочную функцию, поэтому `this` внутри него — это `this`
окружающего метода, а не новый, как у `function` в JS.

### defer

`defer` откладывает вызов до выхода из функции: при `return`, в конце тела или при исключении.

```go
func readConfig(path string) (string, error) {
    const fd = fs.openSync(path, "r")
    defer fs.closeSync(fd)

    const text = fs.readFileSync(fd, "utf8")
    if text == "" {
        return "", error("empty config")
    }
    return text, null
}
```

```js
function readConfig(path) {
  const fd = fs.openSync(path, "r");
  try {
    const text = fs.readFileSync(fd, "utf8");
    if (text === "") {
      return ["", new Error("empty config")];
    }
    return [text, null];
  } finally {
    fs.closeSync(fd);
  }
}
```

Правила, как в Go:

- функция и её аргументы вычисляются в момент `defer`, а сам вызов происходит при выходе;
- несколько отложенных вызовов выполняются в обратном порядке;
- если отложенный вызов бросает исключение, остальные всё равно выполняются;
- `defer` относится ко всей функции, а не к блоку: `defer` в цикле добавляет вызов на каждой
  итерации, и все они выполнятся при выходе из функции;
- `defer` бывает только внутри функций и методов;
- внутри `defer { ... }` нельзя писать `return`, а `break` и `continue` — только во вложенных
  в него циклах: отложенный код не может изменить то, как функция завершилась.

```go
func countdown() {
    for let i = 0; i < 3; i++ {
        defer console.log(i)
    }
}
// countdown() печатает 2, 1, 0
```

Для нескольких действий есть блочная форма, её содержимое выполняется целиком при выходе:

```go
defer {
    conn.close()
    console.log("connection closed")
}
```

Если все `defer` стоят на верхнем уровне тела функции, компилятор выдаёт вложенные
`try/finally`, как в примере выше. Если `defer` стоит внутри `if` или цикла, отложенные вызовы
собираются в стек и выполняются в `finally`.

### Асинхронные функции

```go
async func loadText(url string) (string, error) {
    const response = await fetch(url)
    if !response.ok {
        return "", error(`HTTP ${response.status}`)
    }
    return await response.text(), null
}

const text, err = await loadText("/hello.txt")
```

```js
async function loadText(url) {
  const response = await fetch(url);
  if (!response.ok) {
    return ["", new Error(`HTTP ${response.status}`)];
  }
  return [await response.text(), null];
}

const [text, err] = await loadText("/hello.txt");
```

`async` пишется перед `func`, перед методом класса (`async load() string`), перед литералом
`func` и перед стрелочной функцией (`async x => ...`).

- **Типы результатов — то, что отдаёт `return`;** сама функция возвращает Promise с ними: у
  `loadText` тип `func(string) Promise[(string, error)]`. Поэтому результаты пишутся как у любой
  функции, в том числе несколько; `Promise[string]` как результат async-функции — ошибка.
- **`await p` ждёт Promise и даёт его значение.** Результаты async-функции распаковываются из
  него как из вызова: `const text, err = await loadText(url)`. `await` значения, которое не
  Promise, даёт само значение, как в JS.
- **Где можно `await`:** в async-функциях и на верхнем уровне модуля — модули это ES-модули. Не в
  `defer`: отложенный код выполняется при выходе из функции и ждать не может. Не в разметке: её
  код выполняется заново при обновлениях. Компонент не может быть async: загружайте данные в
  `mount()` или в обработчике события.
- **Обработчик события может быть async:** `onClick={async () => { user = await load() }}`.
  Изменение состояния после `await` обновляет разметку, как любое другое.
- `defer` async-функции выполняется при её завершении, после всего, чего она ждала.

Promise, созданный вручную, получает тип из объявленного:

```go
async func sleep(ms number) {
    const done Promise[number] = new Promise(resolve => setTimeout(() => resolve(ms), ms))
    await done
}
```

### Горутины

```go
func countPrimes(from, to number) number {
    // ...
}

const PART = 1_000_000
const parts = await Promise.all([0, 1, 2, 3].map(i => go countPrimes(i * PART, (i + 1) * PART)))
go countPrimes(0, 100)              // его никто не ждёт
```

```js
const parts = await Promise.all([0, 1, 2, 3].map((i) => $$go("countPrimes", [i * PART, (i + 1) * PART])));
$$go("countPrimes", [0, 100]);
```

`go f(x)` вызывает `f` в воркере: в Web Worker в браузере, в worker thread в Node. Несколько
вызовов идут одновременно, на разных процессорах, а программа продолжает работу, не дожидаясь их.

- **Что вызывает `go`:** функцию, объявленную на верхнем уровне модуля, или импортированную.
  Память у воркера с программой не общая: он загружает функции, которые вызывает `go`, вместе с
  объявлениями и импортами, которыми пользуется их код, но не остальной модуль и не его код
  верхнего уровня. Импортированные модули выполняют свой код верхнего уровня и в воркере.
- **Копии:** воркер получает копии аргументов, а программа — копию результата (structured clone
  из `postMessage`). Поэтому это данные: числа, строки, `bool`, массивы, объекты интерфейсов без
  методов, `Map`, `Set`, `Date`, типизированные массивы, `error`. Функция, экземпляр класса или
  DOM-элемент — ошибка компиляции: их копия потеряла бы методы. Изменение копии не меняет оригинал.
- **Нет общего состояния:** код функции не может пользоваться `let`-переменными модуля — у каждого
  воркера были бы свои, — а также компонентами и разметкой: в воркере нет документа. Значения
  передаются аргументами и возвращаются результатом.
- **Результат:** как выражение `go f(x)` — это Promise того, что возвращает `f`, а для async `f` —
  того, что даёт её Promise: `const n, err = await go load(id)`. Как оператор его никто не ждёт, и
  исключение в нём не перехватывается: в Node оно завершает программу, как panic в Go.
- **Пул:** воркеры модуля запускаются при первом `go`, не больше одного на процессор, и вызов
  уходит свободному воркеру. Воркер выполняет несколько вызовов одновременно, пока они ждут в
  `await`. В Node свободные воркеры не держат программу. `go` внутри горутины выполняется в том же
  воркере.

Модуль воркера лежит рядом с модулем: `mango build app.mango` пишет `app.js` и `app.worker.js`, а
`mango run` компилирует его на лету.

## 5. Условия и циклы

### if

```go
if x > 0 {
    console.log("positive")
} else if x < 0 {
    console.log("negative")
} else {
    console.log("zero")
}
```

Скобки вокруг условия не нужны, фигурные обязательны. Условие должно иметь тип `bool`: в отличие
от JS, никаких truthy/falsy. `if count {` — ошибка, пишем `if count > 0 {`, а вместо `if user {`
пишем `if user != null {`.

Объектный литерал в заголовке `if`, `for` или `switch` берётся в скобки, иначе его `{` спутать с
началом блока (то же правило в Go).

### for — единственный цикл

| MangoScript                     | JS                                          |
| ------------------------------- | ------------------------------------------- |
| `for let i = 0; i < n; i++ { }` | `for (let i = 0; i < n; i++) { }`           |
| `for x in items { }`            | `for (const x of items) { }`                |
| `for i, x in items { }`         | `for (const [i, x] of items.entries()) { }` |
| `for cond { }`                  | `while (cond) { }`                          |
| `for { }`                       | `while (true) { }`                          |

`for x in items` перебирает **значения**, как `for...of` в JS или `for x in` в Python и Rust, а
не ключи, как `for...in` в JS. В Go `for i := range xs` с одной переменной даёт индекс; здесь одна
переменная получает значение, а две — индекс и значение.

`break` и `continue` работают как обычно.

### switch

```go
switch cmd {
case "start", "run":
    start()
case "stop":
    stop()
default:
    console.log("unknown command")
}
```

```js
switch (cmd) {
  case "start":
  case "run":
    start();
    break;
  case "stop":
    stop();
    break;
  default:
    console.log("unknown command");
}
```

Каждый `case` неявно заканчивается `break`, несколько значений перечисляются через запятую.

`switch` без выражения заменяет длинную цепочку `if`:

```go
switch {
case score >= 90:
    grade = "A"
case score >= 75:
    grade = "B"
default:
    grade = "C"
}
```

```js
if (score >= 90) {
  grade = "A";
} else if (score >= 75) {
  grade = "B";
} else {
  grade = "C";
}
```

## 6. Ошибки

Ожидаемые ошибки (некорректный ввод, файл не найден) возвращаются последним значением типа
`error`:

```go
func parsePort(s string) (number, error) {
    const n = Number(s)
    if Number.isNaN(n) || n < 1 || n > 65535 {
        return 0, error(`invalid port: ${s}`)
    }
    return n, null
}

const port, err = parsePort(input)
if err != null {
    console.error(err.message)       // внутри if у err тип Error, а не null
}
```

```js
function parsePort(s) {
  const n = Number(s);
  if (Number.isNaN(n) || n < 1 || n > 65535) {
    return [0, new Error(`invalid port: ${s}`)];
  }
  return [n, null];
}

const [port, err] = parsePort(input);
if (err != null) {
  console.error(err.message);
}
```

`error(msg)` создаёт `new Error(msg)`.

Исключения остаются для JS-кода, который бросает, и для действительно аварийных ситуаций:

```go
let config any
try {
    config = JSON.parse(text)
} catch e {
    console.error("bad config:", e)
} finally {
    console.log("done")
}

throw error("unreachable")
```

`catch` записывается без скобок, `e` имеет тип `any`.

## 7. Классы

Классы как в JS и TypeScript, типы — в стиле Go. Методы объявляются без `func`, как методы
в JS-классах.

```go
class User {
    name string
    private age number             // нулевое значение: 0
    tags []string                  // нулевое значение: []
    static count = 0

    constructor(name string, age number) {
        this.name = name
        this.age = age
        User.count++
    }

    greet() string {
        return `Hi, I'm ${this.name}`
    }

    isAdult() bool {
        return this.age >= 18
    }
}

class Admin extends User {
    protected level number

    constructor(name string, age, level number) {
        super(name, age)
        this.level = level
    }

    greet() string {
        return `${super.greet()} (admin)`
    }
}

const ann = new User("Ann", 30)
```

```js
class User {
  name = "";
  age = 0;
  tags = [];
  static count = 0;

  constructor(name, age) {
    this.name = name;
    this.age = age;
    User.count++;
  }

  greet() {
    return `Hi, I'm ${this.name}`;
  }

  isAdult() {
    return this.age >= 18;
  }
}
```

- `private`, `protected` и `public` (по умолчанию) проверяются только компилятором, как в
  TypeScript. В JS они не попадают, поэтому из JS-кода поля доступны.
- Видимость задаётся модификаторами, а не регистром первой буквы, как в Go.
- К полям внутри методов обращаются через `this`, как в JS.
- Методы могут возвращать несколько значений.
- Поле без значения получает нулевое значение своего типа. Если у типа его нет (класс, интерфейс,
  функция), поле нужно присвоить в конструкторе.

## 8. Интерфейсы

Интерфейс описывает форму значения — поля и методы. Как и в TS, он существует только во время
компиляции.

```go
interface Shape {
    name string
    area() number
}

interface Point {
    x, y number
    label ?string                  // необязательное поле: можно не указывать
}

class Circle implements Shape {
    name = "circle"
    r number

    constructor(r number) {
        this.r = r
    }

    area() number {
        return Math.PI * this.r ** 2
    }
}

func describe(s Shape) string {
    return `${s.name}: ${s.area()}`
}

describe(new Circle(2))               // класс подходит под Shape
const p Point = { x: 1, y: 2 }        // объектный литерал подходит под Point
```

`implements` необязателен: класс подходит под интерфейс, если у него есть нужные поля и методы.
`implements` просто просит компилятор проверить это в месте объявления класса.

## 9. Модули

```go
import { readFileSync, writeFileSync as write } from "node:fs"
import * as path from "node:path"
import express from "express"
import "./setup.mango"

export func greet(name string) string {
    return `Hello, ${name}`
}
export const VERSION = "0.1.0"
export class User { ... }
export interface Point {
    x, y number
}
```

Импорты и экспорты переходят в ES-модули один к одному; `export interface` и `export type` при
компиляции исчезают.

- Имя, которое используется только как тип (например, импортированный интерфейс), из `import`
  убирается: в рантайме такого значения нет.
- `mango build main.mango` пишет `main.js` (и `main.d.ts`, см. ниже) рядом с исходником и так же
  компилирует все `.mango`-файлы, которые он импортирует. В импортах `.mango` заменяется на `.js`:
  `"./geom.mango"` → `"./geom.js"`. `mango build src/` собирает все `.mango`-файлы папки, а
  `--out-dir build/` складывает `.js` в отдельную папку с той же структурой. Если в каком-то
  файле есть ошибки, не пишется ни один файл.
- `mango run` компилирует импортируемые `.mango`-файлы на лету.

### Типы из TypeScript

Типы импортов, которые не являются `.mango`-модулями, берутся из объявлений TypeScript: пакеты с
`types` в `package.json` или с `@types/*`, `.ts`-файлы и модули Node (`node:fs`, `node:http` —
из `@types/node`). Их читает компилятор TypeScript (пакет `typescript`); он загружается, только
если такой импорт есть. Модуль без объявлений, например JS-файл без `.d.ts`, остаётся `any`, без
ошибки.

```go
import { readFileSync } from "node:fs"
import { createServer, IncomingMessage, ServerResponse } from "node:http"

const text = readFileSync("a.txt", "utf8")      // string
const bytes = readFileSync("a.txt")             // Buffer

func handle(request IncomingMessage, response ServerResponse) {
    const url string = request.url              // ошибка: url может быть null (?string)
}
```

Как типы TypeScript переходят в MangoScript:

| TypeScript                                     | MangoScript                                 |
| ---------------------------------------------- | ------------------------------------------- |
| `boolean`, `string`, `number`, литералы, union | `bool`, `string`, `number`, литералы, union |
| `T \| undefined`, `T \| null`, `x?: T`         | `?T`                                        |
| `T[]`, `Array<T>`; кортеж `[A, B]`             | `[]T`; `[](A \| B)`                         |
| `void` в результате                            | функция без результата                      |
| интерфейс, объектный тип, пересечение          | интерфейс                                   |
| класс                                          | класс: `new`, `extends`, `instanceof`       |
| `Box<T>`, `function first<T>(...)`             | дженерики: `Box[T]`, вывод аргументов типа  |
| перегрузки                                     | вызов выбирает первую подходящую сигнатуру  |
| `enum`                                         | union литералов                             |
| `[key: string]: T`                             | неизвестные члены имеют тип `T`             |
| `unknown`, `object`, `symbol`, `bigint`        | `any`                                       |
| условные и mapped-типы, которые TS не свёл     | `any`                                       |

- `import x from "pkg"` — экспорт по умолчанию; у модулей с `export =` это само значение, а
  именованные импорты — его свойства: `import { join } from "node:path"`.
- У параметров типа со значением по умолчанию аргумент можно не писать: `Buffer` — это
  `Buffer[ArrayBufferLike]`. От такого класса можно наследоваться: `class Bus extends EventEmitter`.
- Ограничения параметров типа из `.d.ts` не проверяются.
- В типах нельзя обратиться к типу внутри пространства имён (`http.Server`): его импортируют по
  имени.
- Песочница на сайте работает в браузере без пакета `typescript`, поэтому там такие импорты — `any`.

### Объявления для TypeScript

`mango build` с проверкой типов пишет рядом с каждым `.js` файл `.d.ts`, и TypeScript-код
импортирует модуль MangoScript с типами. С `--no-check` объявлений нет: без проверки типы неизвестны.

```go
export type Filter "all" | "active" | "done"

export func divide(a, b number) (number, error) { ... }

export class Stack[T] {
    private items []T
    push(item T) { ... }
    pop() ?T { ... }
}
```

```ts
export type Filter = "all" | "active" | "done";
export declare function divide(a: number, b: number): [number, Error | null];
export declare class Stack<T> {
    private items;
    push(item: T): void;
    pop(): T | null;
}
```

- `bool` → `boolean`, `?T` → `T | null`, `error` → `Error | null`, `[]T` → `T[]`; поле типа `?T`
  можно не передавать: `note?: string | null`.
- Несколько результатов → кортеж `[A, B]`: функция и в JS возвращает массив.
- Имена параметров берутся из кода, типы — из проверки, поэтому выведенные типы (`const n = 1`)
  тоже попадают в объявления.
- Интерфейсы, `type` и классы объявляются, даже если не экспортированы: на них могут ссылаться
  экспортированные функции. Компонентов в JS нет, и в объявлениях тоже; значение типа
  `comp(title string)` — функция компонента, `(title: string) => [Node, ...unknown[]]`.
- Импорты повторяются с `.js` вместо `.mango`, чтобы в типах были доступны импортированные имена.

### Разметка

Разметка в коде создаёт настоящие DOM-элементы, без виртуального DOM:

```go
const name = "на главную страницу"
const link = <a href="/" class="nav">Ссылка {name}</a>     // HTMLAnchorElement
```

```js
const link = document.createElement("a");
link.href = "/";
link.className = "nav";
link.append("Ссылка ", name);
```

- **Синтаксис как в JSX:** атрибуты `href="/"`, `href={url}`, `disabled`, `{...attrs}`; дети —
  текст, `{выражение}` и элементы; фрагмент `<>...</>`. Имена атрибутов — как в HTML: `class`,
  `for`.
- **Типы:** `<input>` — это `HTMLInputElement`, `<a>` — `HTMLAnchorElement` и т. д. Атрибуты,
  которые соответствуют свойствам DOM, проверяются по типу свойства. Дети — строки, числа, узлы,
  массивы из них или `?T`; `null` не выводит ничего.
- **SVG:** `<svg>`, элементы внутри него и теги, которые есть только в SVG (`<path>`, `<circle>`,
  `<g>`...), создаются в пространстве имён SVG через `createElementNS`, а их атрибуты задаются
  через `setAttribute`. `<a>`, `<title>` и другие теги, которые есть и в HTML, — SVG только внутри
  `<svg>`; дети `<foreignObject>` — снова HTML.
- **Много элементов:** модуль, код которого создаёт больше 20 элементов, создаёт их хелпером,
  который принимает атрибуты, заданные с самого начала,
  `$$element("a", { href: "/", className: "nav" }, { "aria-label": label })`, вместо
  `createElement` и оператора на каждый атрибут. Обработчики, `bind:`, стили, атрибуты, которые
  могут быть `null`, и атрибуты после spread остаются операторами.
- **События:** имя функции, `obj.method` или литерал функции — это обработчик. Всё остальное — код,
  который выполнится по событию, с переменной `event`: `onClick={count++}`,
  `onSubmit={event.preventDefault(); send()}`. Поэтому `onClick={save()}` вызывает `save` по клику.
- **Где вводить разметку.** `<` в начале выражения начинает разметку, после значения — это
  сравнение. Открывающий тег пишется на той же строке, что `return`.
- **Условия и циклы** пишутся внутри `{...}` обычными `if`, `for` и `switch`. Элементы в их блоках
  становятся содержимым; кроме элементов в блоках можно писать только вложенные `if` / `for` /
  `switch` и `const`:

  ```go
  <ul>{for i, product in products {
      if product != null {
          <Product {...product} />
      }
  }}</ul>
  ```

### Компоненты

Компонент существует только при компиляции: каждое его использование заменяется его кодом.

```go
comp Card(title string, kind string = "info", children Content) {
    return <section class={kind}>
        <h2>{title}</h2>
        {children}
    </section>
}

document.body.append(<Card title="Профиль"><p>Текст</p></Card>)
```

- **Объявление.** `comp Name(свойства) { ...; return <разметка> }` — только на верхнем уровне
  модуля. Имя начинается с заглавной буквы. Тело заканчивается `return` разметки.
- **Ранний `return`** тоже возвращает разметку: `if index > 2 { return <div>end</div> }`. Тело
  выполняется один раз, при создании, поэтому и выбор между `return` делается один раз: если потом
  изменится то, что читает условие, компонент останется прежним. Чтобы разметка менялась вместе с
  состоянием, нужен `{if ...}` в разметке.
- **Свойства.** Это параметры в синтаксисе Go; только у них бывают значения по умолчанию. Свойство
  с `?T` или со значением по умолчанию можно не указывать. Атрибуты проверяются как аргументы
  вызова: лишний атрибут или пропущенное обязательное свойство — ошибка.
- **`children Content`** получает разметку между тегами.
- **Spread** `<Product {...product} />` передаёт поля объекта с именами свойств; остальные поля не
  учитываются, а атрибуты после spread его перекрывают.
- **Свойства-функции** (`onPress func()`) принимают код по тому же правилу, что `on*` у элементов.
- **Свойства только для чтения.** Чтобы изменить состояние родителя, передают свойство-функцию.
- **`...attrs`** — последнее свойство — получает атрибуты использования, которые не являются
  свойствами; `{...attrs}` ставит их на один элемент разметки компонента, созданный один раз, а
  использование проверяется так, будто они написаны на этом элементе. Класс или стиль добавляются к
  тем, что есть у элемента.
- **В JS компонента нет:** его код встраивается блоком на месте использования, а значения
  атрибутов вычисляются до этого блока. Исключения — рекурсивные и экспортируемые компоненты и
  компоненты, которые используются как значения, см. ниже, и большие: компонент, копии которого
  добавили бы больше 100 строк по сравнению с функцией и её вызовами, компилируется в функцию.
- **Рекурсивные компоненты** (дерево, вложенные комментарии) не встраиваются, а компилируются в
  функцию. Какое-то использование на цикле должно быть под условием (`if`, `for`, ветка `?:`), иначе
  рекурсия не закончится — это ошибка компиляции.
- **Экспортируемые компоненты** (`export comp Card`) импортируются по имени,
  `import { Card } from "./card.mango"`, и используются как теги. Их модуль компилирует их в
  функции, `export function $$Card(...)`. Модуль, где такой компонент используется, вызывает его
  или встраивает по тому же порогу в 100 строк, вместе с компонентами его модуля, которые он
  использует; имена того модуля приходят через скрытые экспорты, `export { PREFIX as $$Card$PREFIX }`.
  Компонент, который присваивает переменную своего модуля, всегда вызывается: другой модуль может
  её только читать.
- **Компоненты как значения.** `content: Intro` — значение типа `comp()`, а
  `comp(title string, kind ?Kind)` перечисляет свойства с именами. Тег берёт компонент из
  значения: `<section.content />` или `<Page />` с переменной `Page`. Он передаёт свойства в
  порядке типа, поэтому компонент подходит к типу с теми же именами в том же порядке; в конце могут
  быть ещё свойства, если их можно не передавать, а свойство со значением по умолчанию подходит к
  `?T`. Такой компонент — функция, `$$Intro`, и тег её вызывает. Когда значение зависит от
  состояния и меняется, компонент создаётся заново; `ref` и spread на таком теге невозможны.

  ```go
  interface Section {
      title string
      content comp()
  }

  const SECTIONS []Section = [{ title: "Введение", content: Intro }]

  comp Guide() {
      return <main>{for section in SECTIONS { <section.content /> }}</main>
  }
  ```

**Состояние.** `state` объявляет переменную, от которой зависит разметка. Объявляется как `let`, но
только на верхнем уровне тела компонента:

```go
comp Counter(initialValue number) {
    state count = initialValue
    return <button onClick={count++}>Нажато {count} раз</button>
}
```

```js
let count = initialValue;
const $$button3 = document.createElement("button");
$$button3.addEventListener("click", () => {
  count++;
  $$text4.data = count;
});
const $$text4 = document.createTextNode(count);
$$button3.append("Нажато ", $$text4, " раз");
```

- **Что обновляется.** Разметка, которую компонент создаёт один раз: та, что он возвращает, и
  элементы, объявленные на верхнем уровне тела (`const input = <input />`). Текст и атрибуты, которые
  читают состояние, обновляются на месте. Узлы, которые от него зависят (`{items.map(...)}`,
  `{ok ? <b /> : null}`), создаются заново. Свойство дочернего компонента, которое получает
  состояние, тоже обновляется.
- **Что считается изменением:** присваивание и `++` переменной или её полей (`user.name = "Ann"`),
  изменяющие методы массивов (`push`, `splice`, `sort`…) и методы объектов, кроме известных
  читающих. Изменения через переменные, которые указывают внутрь состояния (`for todo in todos`,
  `todos.map(todo => ...)`), тоже видны. Изменения внутри функций, которым передали состояние, не
  видны: тогда помогает присваивание `todos = todos`.
- **Когда.** Изменения в обработчиках событий и функциях компонента обновляют разметку сразу.
  Изменения в самом теле компонента, до `return`, ничего не обновляют: разметки ещё нет, и она
  создастся уже с новыми значениями. Не обновляют и изменения в коде отрисовки: в выражениях
  разметки и в функциях, которые она вызывает.

Внутри компонента `{if ...}`, `{for ...}` и `{switch ...}`, которые зависят от состояния, тоже
обновляются: ветка создаётся заново, только когда меняется выбор, а блоки списка находятся по
самому элементу массива и при изменениях переставляются, а не создаются заново.

**Производные значения.** `derived double = count * 2` на верхнем уровне тела компонента — значение,
вычисленное из состояния и свойств. Его читают, как константу, а присваивание ему — ошибка. Когда
то, что оно читает, меняется, оно вычисляется заново, до обновления разметки, которая его читает:

```go
comp Counter(initialValue number) {
    state count = initialValue
    derived double = count * 2
    return <button onClick={count++}>{count} × 2 = {double}</button>
}
```

```js
let count = initialValue;
let double = count * 2;
// ...создание узлов...
function $$updateCount2() {
  double = count * 2;
  $$text5.data = count;
  $$text6.data = double;
}
```

- Это одно имя и одно выражение; тип можно записать: `derived left number = ...`. Объявляется
  только в компоненте (или декораторе), как `state`.
- Оно вычисляется заново и тогда, когда тело компонента меняет состояние до того, как появилась
  разметка, поэтому оно верно везде, где его читают. Значение, которое не читает ни состояния, ни
  свойств, получающих состояние родителя, — константа.

**Эффекты.** `effect { ... }` на верхнем уровне тела компонента выполняется, когда разметка
создана, и снова после обновлений, когда меняется то, что он читает. То, что он читает, — это то,
что читает его код, пока выполняется: не в функциях, которые он создаёт (`setInterval(() => ...)`),
и не в его `defer`, и не переменные, которые он записывает. Убирает за собой он через `defer`:
отложенный вызов выполняется перед следующим запуском эффекта и когда `{if}`, `{switch}` или
`{for}` удаляют компонент.

```go
comp Todos() {
    state todos []string = load()
    // Сохраняется заново при каждом изменении списка.
    effect {
        localStorage.setItem("todos", JSON.stringify(todos))
    }
    // ...
}
```

- Эффект ничего не возвращает. В отличие от `mount()`, он не ждёт, пока разметка окажется в
  документе, и выполняется снова.
- Эффект после раннего `return` компонента может не создаться, поэтому, как и разметка там, он не
  выполняется снова при изменениях.

**Двусторонняя привязка.** `bind:value={name}` у `<input>`, `<textarea>` и `<select>` и
`bind:checked={done}` у `<input>` показывают значение переменной и записывают в неё то, что ввёл
пользователь. Привязать можно то, чему можно присвоить: переменную или поле. Тип — `string`,
`number` (только `<input type="number">` и `type="range"`) или `bool` для `checked`.

**Монтирование.** `mount() { ... }` на верхнем уровне тела компонента выполняется, когда его
разметка уже на странице. Функция, которую он вернул, выполняется, когда разметку убирает
`{if}`, `{switch}`, `{for}` или ветка `?:` в разметке:

```go
comp Clock() {
    state time = new Date().toLocaleTimeString()
    mount() {
        const timer = setInterval(() => {
            time = new Date().toLocaleTimeString()
        }, 1000)
        return () => clearInterval(timer)
    }
    return <p>Сейчас {time}</p>
}
```

- **У каждого экземпляра.** `mount` выполняется для каждого созданного компонента: у списка из
  двух `<Fruit />` — два раза. Чтобы сделать что-то один раз для всего списка, `mount` пишут в
  компоненте, который этот список создаёт.
- **Когда.** Только когда разметка в документе. Это проверяется в микрозадаче после кода, который
  создал компонент: к этому моменту `document.body.append(...)` или ветка `{if}` обычно уже
  вставили разметку, а браузер ещё не нарисовал кадр, поэтому работают `focus()` и замеры размеров.
  Разметка, созданная заранее и вставленная позже (`const card = <Card />`, а потом
  `document.body.append(card)` в таймере), монтируется, когда её вставят: пока какая-то разметка
  ждёт, за документом следит `MutationObserver`. Если `{if}`, `{switch}` или `{for}` уберут
  разметку раньше, `mount` не выполнится.
- **Тело `mount`** — функция, которая выполняется позже, как обработчик события: изменения
  состояния в ней обновляют разметку, а `return` относится к ней, а не к компоненту.
- **Что возвращает:** ничего, функцию без параметров, которая всё останавливает, или `null`, если
  останавливать нечего.
- **Кто вызывает очистку.** Блоки `{if}`, `{switch}` и `{for}` знают, какие компоненты в них
  созданы, включая вложенные блоки, и при удалении вызывают их очистку. Разметка, которую
  программа вставила сама (`document.body.append`) и удаляет сама, этого не делает: её очистка не
  вызывается.
- `mount` можно написать несколько раз; они выполняются по порядку.
- `mount` — ключевое слово только в начале оператора в теле компонента: функция с именем `mount`
  в других местах — обычная функция.

```js
$$mount(() => {
  const timer = setInterval(() => { ... }, 1000);
  return () => clearInterval(timer);
});
```

**Ссылки на элементы.** `ref имя` на верхнем уровне тела компонента или декоратора даёт имя
элементу его разметки, а сам элемент задаёт `ref={имя}`:

```go
comp Search() {
    ref input
    mount() {
        input.focus()
    }
    return <form class="search">
        <label for={input.id}>Найти</label>
        <input id="query" ref={input} />
    </form>
}
```

```js
const input = document.createElement("input");
input.id = "query";
$$mount(() => $$mountNode2, () => {
  input.focus();
});
// ...разметка заполняет элемент, а не создаёт его:
$$label3.htmlFor = input.id;
```

- **Элемент есть с самого начала.** Он создаётся там, где объявлен ref, вместе с постоянными
  атрибутами: записанными строкой или без значения, до первого `{...spread}`. Остальное задаёт
  разметка там, где она написана: значения в `{...}`, обработчики, `bind:` и детей. Поэтому ref
  никогда не бывает `null`, и разметка может ссылаться на элемент, записанный ниже.
- **Тип** — тип элемента (`HTMLInputElement`) или указанный: `ref input HTMLElement`. Присвоить
  ref нельзя, и состоянием он не является.
- **Один раз.** Ref связывается с одним элементом в разметке, которая создаётся ровно один раз:
  то, что даёт `return`, `const x = <...>` на верхнем уровне тела, дети компонентов в ней и обёртка
  декоратора — для ref самого декоратора. Внутри `{if}`, `{for}`, `{switch}`, выражений и функций
  ref — ошибка. Если ранний `return` дал другую разметку, элемент остаётся таким, каким был
  объявлен, вне документа.
- **Ref на компонент,** `<Card ref={card} />`, указывает на элемент наверху того, что создаёт
  `Card`, с учётом обёрток его декораторов. Этот элемент создаёт ref, а `Card` его заполняет:
  встроенный — напрямую, функция — через последний аргумент `$$root`. На компонент с несколькими
  `return`, на компонент, который возвращает фрагмент, и на обёртку, которая возвращает другое
  выражение, указать нельзя: элемент заранее неизвестен. Свойство с именем `ref` у компонента
  быть не может.

**Стили.** `style { ... }` на верхнем уровне тела компонента или декоратора — CSS для его
собственной разметки:

```go
comp Badge(color string) {
    style {
        .badge { padding: 2px 8px; background: {color}; }
    }
    return <span class="badge">new</span>
}
```

- **Область.** Элементы собственной разметки компонента получают класс `mango-badge-<хэш>`, и
  каждый составной селектор тоже, поэтому правила не задевают ни остальную страницу, ни разметку
  `children` и других компонентов. `:global(...)` оставляет селектор как есть.
- **Значения из кода.** `{expr}` в значении объявления (`имя:` с пробелом или значением после
  двоеточия) — строка или число. Значение становится CSS-переменной, которую компилятор ставит на
  элемент, возвращённый компонентом, и снова — когда меняется то, что значение читает.
- **CSS** один раз добавляет в `<head>` код модуля, через `$$style`. Селектор, который не совпадает
  ни с одним элементом разметки, — предупреждение, оно не останавливает компиляцию.

**CSS-модули.** `import styles from "./button.module.css"` читает файл при компиляции. Его классы
получают собственные имена, `button_14zwdg2`, а `styles` — объект из них: у его типа есть поле
`string` на каждый класс, поэтому `styles.buton` — ошибка компиляции, и `styles[kind]` при
`kind "primary" | "ghost"` тоже проверяется. Теги, `:root` и `:global(...)` остаются
глобальными. Импорт становится объектом, а CSS модуль добавляет на страницу через `$$style`; файл
во время работы не импортируется, поэтому это работает и с `mango build`, и с Vite. Класс, который
модуль нигде не называет, — предупреждение, если только модуль не читает `styles` по ключу,
значение которого неизвестно.

**Веб-компоненты.** `@html-tag` перед `comp` делает компонент ещё и пользовательским элементом, и
он работает в обычном HTML, в других фреймворках и из JS. Тег — имя компонента в kebab-case или тот,
что указан в декораторе:

```go
@html-tag comp mainPage() { ... }               // <main-page>
@html-tag("app-card") comp Card(title string) { ... }   // <app-card>
```

- **Имя** подчиняется правилам HTML: строчные буквы, цифры, `-`, `.` и `_`, начинается с буквы,
  есть хотя бы один дефис, и это не одно из имён, зарезервированных HTML (`font-face`...). Имя,
  которое их нарушает, или тег, занятый двумя компонентами, — ошибка компиляции. Без имени в
  декораторе компонент может начинаться со строчной буквы: `@html-tag comp mainPage()`.
- **Отрисовка.** Элемент создаёт разметку компонента в своём shadow root, когда его подключают к
  документу. Когда его отключают и не вставляют обратно в той же задаче, разметка удаляется и
  выполняются функции, которые вернул `mount()`; при перемещении элемента разметка и состояние
  сохраняются. `children` — это `<slot>`.
- **Свойства.** Каждое свойство, кроме `children`, — JS-свойство элемента; присваивание обновляет
  разметку. У свойств типа `string`, `number` или `bool` (а также nullable, литеральных типов и их
  объединений) есть ещё и атрибуты: `itemCount` — это `item-count`. Атрибут преобразуется по типу:
  строка как есть, число через `Number()`, bool равен `true`, когда атрибут есть. Без атрибута у
  свойства значение по умолчанию. Массивы, объекты и функции — только JS-свойства.
- **Незаданные свойства.** У элемента, написанного в HTML, нет свойств, пока их не зададут, поэтому
  свойство без значения по умолчанию получает нулевое значение (`""`, `0`, `false`, `[]`, `null`).
  Свойству, у типа которого нет нулевого значения, нужно значение по умолчанию или nullable-тип.
  Свойства нельзя называть как свойства `HTMLElement`, нужные элементу: `id`, `style`, `hidden`,
  `className`, `slot`...
- **В разметке того же модуля** `<app-card title="Привет" item-count={2} />` задаёт свойства
  напрямую, поэтому они проверяются как свойства компонента и могут быть объектами или функциями.
- **Регистрация.** `customElements.define` вызывается в конце модуля, когда у имён, которые
  использует компонент, уже есть значения. Свойства, заданные элементу до этого, сохраняются.

```js
class $$CardElement extends HTMLElement {
  static observedAttributes = ["title"];
  connectedCallback() { /* $$Card(...) в this.shadowRoot */ }
  disconnectedCallback() { /* очистка mount() */ }
  attributeChangedCallback(name, old, value) { /* this.title = value ?? undefined */ }
  set title(value) { /* обновляет разметку */ }
}
customElements.define("app-card", $$CardElement);
```

**Декораторы.** `dec имя(параметры) { ... }` объявляет логику, которая добавляется к компонентам,
к которым он применён: состояние, функции, `mount()` и обёртку вокруг того, что возвращает
компонент. Декоратор применяется как `@имя(аргументы)` перед `comp`; как и компонент, он существует только при компиляции, и его код встраивается в каждый
компонент.

```go
dec counter(start number = 0) {
    public state count = start
    let clicks = 0

    public func add() {
        count++
        clicks++
    }

    mount() {
        console.log("counting from", start)
    }
}

@counter(5)
comp Clicker(label string) {
    return <button onClick={@counter.add()}>{label}: {get(@counter.count)}</button>
}
```

- **Параметры** записываются как у функций, но в конце у них могут быть значения по умолчанию.
  Аргументы позиционные; без аргументов скобки можно опустить: `@counter`. Они вычисляются для
  каждого экземпляра, и в них видны свойства компонента, поэтому `@counter(label.length)` работает;
  когда свойство меняется, аргумент вычисляется заново. Внутри декоратора параметры только для
  чтения.
- **В теле** могут быть `state`, `const`, `let`, `ref`, `style`, функции, `mount()` и в конце — `return`
  обёртки; ref связываются в разметке обёртки. Свои имена в нём используются как обычно; компонент
  их не видит, если они не `public`.
- **Публичные члены** — `public state`, `public derived`, `public const` и `public func`;
  `public let` нет. Компонент читает состояние, производные значения и константы через
  `get(@counter.count)` (в разметке это обновляется, как его
  собственное состояние) и вызывает функции как `@counter.add()`. Вне декоратора его члены только
  для чтения: `get(@counter.count) = 0` или `get(@counter.items).push(x)` — ошибка, изменения идут
  через его публичные функции. `get` особый, только когда его аргумент начинается с `@`.
- **Декоратор не видит компонент**, только свои аргументы, поэтому подходит любому компоненту.
- **Обёртка** `return (content Element) => ...` получает то, что вернул компонент, а то, что она
  возвращает, — это то, что компонент даёт в итоге. Это функциональный литерал с одним параметром,
  тип которого записан явно: он ограничивает, к чему можно применить декоратор
  (`(form HTMLFormElement) => ...` подходит только компонентам, которые возвращают форму), а тип
  `<Clicker />` — это то, что возвращает самая внешняя обёртка. Обёртка вызывается один раз, при
  создании компонента; чтобы позже показать другое, её разметка читает состояние декоратора и
  обновляется, как собственная разметка компонента. Обёртка возвращает один раз, в конце своего
  тела.
- **Зависимости.** Декоратор видит публичные члены другого, только если называет его после своих
  параметров: `dec cartBadge() needs cart, auth { ... }`. Его тело может сразу читать их
  состояние, поэтому они должны быть применены выше: `@cart @cartBadge comp ...`. Взаимные
  зависимости (`a` нужен `b`, а `b` нужен `a`) — ошибка.
- **Несколько декораторов**, `@a @b comp X`: тела выполняются сверху вниз, затем тело компонента;
  обёртки применяются снизу вверх (результат компонента идёт в `b`, результат `b` — в `a`);
  `mount()` — изнутри наружу (компонент, `b`, `a`), очистка — в обратном порядке. Повторное
  применение декоратора — ошибка, а `@html-tag` должен стоять первым.
- **Имена модуля**, которые используют декоратор и его аргументы, нельзя объявлять в компоненте:
  код декоратора выполняется внутри компонента.
- `dec` — ключевое слово только в начале объявления на верхнем уровне модуля.
- **Модули.** `export dec` экспортирует декоратор; другой модуль импортирует его по имени,
  `import { counter } from "./counter.mango"`, и применяет как обычно. Его код встраивается туда, а
  имена его собственного модуля, которые он использует, приходят через скрытые экспорты:
  `export { log as $$counter$log }` в его модуле, `import { $$counter$log } from "./counter.js"`
  там, где он применён. Поэтому экспортируемый декоратор не может присваивать переменные своего
  модуля (другие модули могут их только читать), а декораторы, которые ему нужны, тоже
  экспортируются. Компоненты его модуля, которые использует его код, идут вместе с ним, как у
  встроенного компонента из другого модуля; компоненты и декораторы, которые их модуль
  импортирует, они пока использовать не могут.
- Ещё нет: переименования декоратора при импорте, `return` внутри `if` или `for` обёртки и
  объединения декораторов.

```go
dec notFound() {
    state missing = false

    public func show() {
        missing = true
    }

    return (page Element) => <div class="page">{missing ? <NotFoundPage /> : page}</div>
}
```

В JS код декоратора попадает в блок компонента, а его имена получают префикс. Обёртка встраивается
там, где компонент возвращает разметку: сначала создаётся его разметка, в переменной параметра
(`$$notFound$page`), затем разметка обёртки вокруг неё.

```js
const $$counter$start = 5;
let $$counter$count = $$counter$start;
let $$counter$clicks = 0;
function $$counter$add() {
  $$counter$count++;
  $$updateCounter$count2();
  $$counter$clicks++;
}
```

Полная концепция, включая реактивность, — в [docs/components.ru.md](components.ru.md).

## 10. Операторы: отличия от JS

| MangoScript       | JS          | Примечание                                            |
| ----------------- | ----------- | ----------------------------------------------------- |
| `a == b`          | `a === b`   | нестрогого сравнения в языке нет                      |
| `a != b`          | `a !== b`   |                                                       |
| `x == null`       | `x == null` | остаётся нестрогим: ловит и `null`, и `undefined`     |
| `a = b`, `a += b` | то же       | только как оператор: `f(a = 1)`, `a = b = c` — ошибка |
| `i++`, `i--`      | то же       | только как оператор: `a = i++` — ошибка; `++i` нет    |
| `&&`, `\|\|`, `!` | то же       | только для `bool`; значение по умолчанию — через `??` |
| `a + b`           | то же       | числа или строки; `"a" + 1` — ошибка, нужен шаблон    |
| `x as T`          | `x`         | типы должны быть связаны, см. ниже                    |
| `delete obj.key`  | то же       | только как оператор, см. ниже                         |

Остальное как в JS: арифметика, сравнения, битовые операции, `**`, `??`, `?.`, `? :`, `typeof`,
`instanceof`, `new`, spread `...`, индексация `xs[i]`.

В языке нет: `var`, `function`, `===`, `while`, `do...while`, `for...in`, `with` и оператора
запятой.

- **`value as Type`** позволяет смотреть на значение как на другой тип, как в TypeScript, и ничего
  не оставляет в JS. Типы должны быть связаны, один присваиваем другому:
  `element as HTMLInputElement` и `JSON.parse(text) as Config` проходят, `count as string` —
  ошибка. `as` связывает как сравнение: `a + b as number > c` — это `((a + b) as number) > c`.
  Переменная с именем `as` остаётся обычным именем.
- **`delete obj.key`** удаляет ключ словаря (`{ [string]: T }`), поле типа `?T` или поле у `any`;
  обязательное поле удалить нельзя, а для массива нужен `splice`. Это оператор, в том числе в
  обработчиках, и в компоненте он обновляет то, что читает объект. `delete` — ключевое слово только
  в начале оператора.

Отдельным оператором может быть только вызов функции или `new`, как в Go: строка `a + b` или
`user.name` сама по себе — ошибка. Так ловятся опечатки и перенос перед бинарным оператором:

```go
const total = price
    + tax              // ошибка: после price уже стоит ;, а "+ tax" ничего не делает
```

## 11. Проверка типов

Компилятор проверяет типы до генерации JS; программа с ошибками типов не компилируется
(`mango build --no-check` пропускает проверку).

```
hello.mango:4:17: error: cannot use ?User as User: it may be null, check it first
hello.mango:7:13: error: "u" may be null: check it with "if u != null" or use "?."
hello.mango:9:11: error: cannot add string and number: use a template string, e.g. `${a}${b}`
```

### Что проверяется

- Типы значений в объявлениях, присваиваниях, аргументах и `return`; число аргументов и
  возвращаемых значений; `missing return`, если функция с результатом может дойти до конца тела.
- Null-safety: обращение к полям и методам `?T`, передача `?T` туда, где ждут `T`.
- Условия `if`/`for`/`?:` и операнды `&&`, `||`, `!` — только `bool`.
- Операторы: `+` для двух чисел или двух строк, арифметика только для чисел, `==` только для
  сравнимых типов.
- Имена: неизвестные переменные и типы, присваивание константам и переменным цикла, `_` как
  значение.
- Классы: видимость `private`/`protected`, аргументы конструктора, вызов `super(...)` в
  конструкторе наследника, совместимость переопределённых методов, `implements`, поля без нулевого
  значения, которым не присвоено значение.
- Объектные литералы: недостающие поля, лишние поля (вероятная опечатка), типы полей.

### Сужение типов

Тип локальной переменной или параметра сужается с `?T` до `T`:

- внутри `if x != null { ... }` и в ветках `?:`;
- после `if x == null { return }` (а также `throw`, `break`, `continue`);
- в правой части `x != null && x.ok` и `x == null || x.ok`;
- в теле цикла `for x != null { ... }`;
- после присваивания значения, которое не может быть `null`.

Так же сужаются union-типы:

- `typeof x == "string"` оставляет члены, для которых `typeof` даёт `"string"`, а `!=` — остальные;
  у `any` это сужает до `string`, `number` или `bool`;
- `x instanceof Point` оставляет экземпляры `Point`, а в ложной ветке убирает их;
- `filter == "all"` сужает union литералов до `"all"`, а `!=` убирает `"all"`;
- в `switch filter { case "active": ... }` в каждой ветке `filter` — литералы её `case`, а в
  `default` — те, что не попали ни в один `case`.

Присваивание переменной сбрасывает сужение. В цикле не сужаются переменные, которые в нём
меняются. В замыкании сужение сохраняется только для констант и переменных, которые нигде не
переприсваиваются.

### Вывод типов

- `let x = value` получает тип значения; `null` и `[]` без объявленного типа — ошибка.
- Параметры стрелочной функции берут типы из контекста: `xs.map(x => x * 2)`,
  `apply(n => n > 0)`. Результат стрелочной функции выводится из тела.
- Тип элементов массива — общий тип всех элементов: `[1, null]` — это `[]?number`.

### Встроенные типы JS

Типы стандартной библиотеки JS и DOM берутся из lib-файлов TypeScript (`lib.es2024`, `lib.dom`)
и глобальных `@types` (например, `process` и `Buffer` из `@types/node`):

- `document`, `window`, `fetch`, `Promise`, `Map`, `Set`, `Date`, `URL`, `Object`… типизированы:
  `document.getElementById("app")` — это `?HTMLElement`, `new Map()` при
  `let m Map[string, number]` — `Map[string, number]`, а `m.get(k)` — `?number`;
- `<input>` создаёт `HTMLInputElement` со всеми членами из `HTMLElementTagNameMap`;
- `event` в `onClick` — `PointerEvent`, в `onKeyDown` — `KeyboardEvent` (из `HTMLElementEventMap`),
  а `event.currentTarget` — сам элемент. `event.target` — `?EventTarget`, как в TypeScript;
- `x instanceof HTMLInputElement` сужает тип, хотя в lib.dom это не класс, а конструктор;
- у строк, чисел и массивов есть все методы из `String`, `Number` и `Array<T>`.

Часть типов написана вручную и важнее lib: `console`, `Math`, `JSON`, `Number`, `String`,
`Boolean`, `parseInt`, `parseFloat`, `setTimeout`/`setInterval`, `Error`, `error` и основные
методы строк, чисел и массивов (`find`, `pop` и `at` возвращают `?T`). Так программа проверяется
одинаково в Node и в браузере.

В браузере (песочница на сайте) компилятора TypeScript нет: там работают только типы, написанные
вручную, а остальные глобальные объекты (`document`, `fetch`, `Map`…) имеют тип `any`.

Типы из импортированных `.mango`-модулей проверяются: компилятор читает эти модули сам. Типы
остальных импортов берутся из объявлений TypeScript (раздел 9).

## 13. Не входит в v0

- **`map[K]V`**, компилируется в `Map`: `m[k]` → `m.get(k)`, `m[k] = v` → `m.set(k, v)`.
- **Классы:** геттеры и сеттеры, `readonly`, абстрактные классы, параметры-свойства конструктора
  (`constructor(private name string)`).
- **`if` с инициализацией:** `if const v, err = f(); err != null { }`.
- **Метки** для `break`/`continue`.
- **Литералы регулярных выражений** `/.../g`. Пока — `new RegExp("...", "g")`.
- **Source maps.**
- **WASM-бэкенд** для подмножества языка (числа, массивы, классы).

## Открытые вопросы

1. **Функции, которые возвращают объект и ошибку.** У класса нет нулевого значения, поэтому
   функция, которая может вернуть ошибку, должна вернуть `(?User, error)`. Вызывающему коду тогда
   нужны две проверки:

   ```go
   const user, err = loadUser(id)
   if err != null {
       return
   }
   if user != null {                 // вторая проверка — только ради типа
       console.log(user.name)
   }
   ```

   Предложение: разрешить сигнатуру `(User, error)` с `return null, err` и считать, что после
   проверки `err != null` значение уже не `null`. В рантайме ничего не меняется, это правило только
   для проверки типов.
